# 开发设备应用

在仓库根目录操作。先阅读 `docs/app-framework.md`，再按功能读取 `framework/include/esphook/app.h`、`app_ui.h`、`app_services.h`，以及“公共 API 速查”列出的 `app_math.h`、`app_rand.h`、`app_sync.h`、`app_command.h`、`app_best.h`。应用只能 include `esphook/app*.h`（外加 C 标准库、cJSON、自己的头），不要碰 FreeRTOS/ESP-IDF/`app_runtime.h`（`check-apps.py` 会拒绝）。参考 `apps/demo/firmware/app.c`；投篮和做 T 展示独立模型及 PC 分工。

1. 用 `python3 scripts/new-app.py <id> --title '<最多四个汉字>' [--pc]` 创建应用。检查新目录，保留 `manifest.json` 中的真实源文件列表。CMake 自动发现，无需修改中央分派器或注册数组。
2. 将逻辑放在 `apps/<id>/firmware`。用 descriptor 的 `on_enter/on_leave/on_event/on_tick/render` 实现生命周期；把可单测的规则与 LVGL 绘制分开。
3. 把本次会话状态放在 `ctx->state`，用 `_Static_assert` 检查 2048 字节上限。仅在 `ctx->root` 下创建控件，退出后不能再持有控件或状态地址。字体、代码图标、确认圆和绘图缓冲优先复用 `app_ui`：共享画布用 `app_ui_canvas(root,x,y,w,h)` + `app_ui_canvas_refresh()`，画布下的 16px 状态条用 `app_ui_band()`，按住进度线用 `app_ui_hold_bar()`；整数数学、确定性随机和固定步长（`app_math.h`、`app_rand.h`、`app_step_take`）不要在核心里再写一份，核心逻辑保持纯 C 以便主机测试。
4. 接收 `APP_EVENT_SHORT` 和 `APP_EVENT_CONFIRM`，需要暂停时再接 DOWN/UP，并处理 APP_EVENT_CANCEL：恢复临时暂停、不成交、不当作短按。实体/USB 共用此事件，USB 失联或租期到期会取消。复用全局 25ms 消抖、500ms 确认、800ms 三击导航，不在应用中另写 GPIO 或三击/双击逻辑（双击回上一个应用也是框架的：`app_back(ctx)` 是它的程序接口，`app_set_double_back(ctx, false)` 单独关闭，屏蔽三击时双击随之关闭）。靠连按的游戏在 `on_enter` 调 `app_set_triple_exit(ctx, false)` 屏蔽三击（切换应用自动恢复），并用 `app_set_exit_hold(ctx, 2000)` 留一个按住 2 秒的出口（平静画面开启、战斗中关闭即可：框架只统计按下时出口已开启的那一按，不用自己记“这一按开始于游戏中”），提示用“按住2秒退出”、进度线用 `app_ui_hold_line()`。导航请求延后到回调返回才提交，提交会消费本次松手。游戏要保存最高分：进入时 `core.best = app_best_get(ctx)`，一局结束时 `app_best_record(ctx, core.best)`（`esphook/app_best.h`，按应用 id 自动分库、只在破纪录时写 flash、结算画面每帧调用也安全；不要在得分每涨一次时记），不要自己拼 `app_storage` 的键。
5. 通过 `app_radar_read` 读快照，通过 `app_servo_request` 排队控制舵机。用 app_hardware_info 查询运行配置/状态，available/online 区分驱动支持和收到有效帧；屏幕和 PWM 舵机无反馈，不伪报实物检测。只有明确的用户确认动作才 ARM；从不自动上电动作。应用退出释放舵机租约并 disarm。后台跟随服务保留校准、限位和限速；校准用 `app_servo_cal_read/apply`（舵机已通电时也生效但不会通电，参考 `apps/servocal`），不要自己改运动服务的配置。游戏要摇舵机或把舵机当方向盘时用 `app_haptic.h`（按限位/限速换算，缺失或未启用时静默），雷达/按键左右转向用 `app_steer.h`；启用舵机只能由玩家在标题/待机画面长按 500ms 触发，并保证游戏中的按键不触发启用（参考 `apps/starship`、`apps/racing`）。
6. 要在不在屏幕上时被打开（闹钟、整点报时、游戏里的定时提醒）：用框架的全局闹钟 API `esphook/app_alarm.h`，不要自己轮询时钟。在 `init()` 里先 `app_alarm_cancel_owner(自己的 id)` 再用 `app_alarm_add(&spec)` 登记（CLOCK 每个本地时间、AT 绝对时刻、AFTER 登记后 N 秒不需要校时；`idle_only` 只在待机时响；`target` 缺省是自己，也可以指向 `"alarm"` 借用它的响铃画面），框架到点打开目标应用并发 `APP_EVENT_ALARM`（`e->key` 是条目 id、`e->text` 是 label）；响铃时用 `app_alarm_snooze/done` 回答，离开应用就算 done，设置变了再 `app_alarm_update`（说同样的话不会打断响铃）。注册表只在 UI 任务和 `init()` 里碰，USB `command` 回调不能直接调用；注册表在 RAM，重启后靠 `init()` 重新登记，设置用 `app_storage_load/save`（≤64 字节、带版本号和范围校验、只在玩家修改时写）；时间用 `app_time_read()`（未校时 `valid=false`，必须处理）。舵机仍然只能由玩家明确启用：闹钟的“舵机提醒”开关是持久的明确选择，只作用于它自己的条目，是唯一的例外，参考 `apps/alarm`。USB 命令前缀自己认领：`command(line)` 在 USB 任务里只校验、答复（`app_command_is/reply/replyf`）、请求切换（`app_command_open/menu`），状态由 UI 任务用 `app_shared_copy` 发布一份纯数据快照再读取（`app_sync.h`），参考 `apps/mirror` 和生成模板。
7. 用 `app_hook_read/reply` 复用通知与异步回传。用 `APP_EVENT_MESSAGE` 接收 PC 消息；事件 text 只在回调期间有效。PC 网络、历史数据和大型计算移到 `apps/<id>/pc`，参考 `docs/app-pc-protocol.md`。
8. 按 `docs/app-framework.md` 的验证步骤运行受影响模型测试、`scripts/check-apps.py`、框架测试和真实 LVGL 无屏测试。需要交付固件时构建机器人和 legacy 两种配置，记录槽位占用。主机渲染通过不等于实机帧率已验证。

给可选应用设置 `APP_STANDBY` 才会出现在待机选择中；再加 `APP_DEFAULT_STANDBY` 可成为未保存选择时的默认待机（全工程最多一个，现为 wedding）。`APP_NOTIFICATIONS` 指定待机收到通知时的接收应用，`APP_HIDDEN` 隐藏系统入口。开机前必须先做的设置（例如没保存过屏幕调整时先把屏幕调对）用 descriptor 的可选 `first_run()`：启动时问一次，答 `true` 的第一个应用排在待机之前，进入时 `ctx->first_run` 为真，做完调 `app_idle(ctx)`（框架接着按目录顺序问后面的应用，都问完才进待机）；要自己防止误退出（关三连按）并设无人操作的超时，参考 `apps/screentest`、`apps/servocal`。菜单标题保持短小，长正文使用滚动标签。避免每帧分配内存、阻塞等待或联网；共享画布仅当前应用使用。
