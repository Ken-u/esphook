# 舵机校准

只用 K1 校准舵机的中位、摆幅、方向和速度，不需要 PC。**装了舵机的机器人（robot 配置）第一次开机，在屏幕设置之后会自动进入**，保存后才进入待机；之后也可以从菜单最后的“舵机校准”重调。命令行的做法（`robot center_us:` 等）仍然可用，见 [robot-bringup.md](robot-bringup.md)。

## 安全

- **先不要装舵盘（舵机头上的转接件）。** 第一页就是这句话。
- 舵机只在第一页**长按 500 ms** 之后才通电（回中），这就是明确的确认；没有别的方式会让它通电。
- 退出应用（保存、跳过、超时、三击、USB 切走）一律关闭舵机输出；运动服务照常执行限位和限速。
- 没有舵机（auto / screen 配置，或舵机驱动不可用）时，应用只在第一页说明原因，开机也不会问；见下面“舵机没反应”。

## 五页

| 页 | 画面 | 短按 | 长按（500 ms，金色进度线） |
| --- | --- | --- | --- |
| 1/5 | 先别装舵盘 / 长按 解锁并回中 | 返回菜单（首次开机里是“先跳过”：不保存，下次开机再问） | 舵机通电并回中，进入第 2 页 |
| 2/5 | 中位 `1500us`，舵机应停在正中 | 中位 +10 us（1400..1600，到头回到 1400），舵机立刻跟着转 | 下一页 |
| 3/5 | 摆幅 `±30°`，左右各转这么多 | 摆幅 +5°（5..45，到头回到 5），舵机来回扫一遍新范围 | 下一页 |
| 4/5 | 方向 `正向`/`反向`，应先朝你的左边转 | 翻转方向，舵机朝正方向点一下头 | 下一页（“对了”） |
| 5/5 | 速度 `35°/s`，越大转得越快 | 换档：15 → 25 → 35 → 50 → 70 → 90 → 15，舵机用新速度来回扫 | **保存**、关闭舵机并离开 |

- 第 2、3 页的值要一起满足运动服务的限制（中位 ± 摆幅换算的脉宽必须落在 1000–2000 μs），装不下的组合会被跳过：中位在 1400 时，摆幅 40° 和 45° 不会出现。
- 画面下方的细条是舵机当前的指令角：**向左是正角度**（站在机器前面的人的左边，也就是传感器的 +X 一侧）。方向对的时候，舵机的头应该先朝你的左边转；转反了就在第 4 页短按一次。绿色小竖线标出摆幅两端。
- 中位这一步要在空载时做：转到舵机应该停的正中位置，再装舵盘；调中位时舵机每次都会立刻回到新的中位脉宽。

## 舵机没反应

**接上了舵机却一点反应没有，最常见的原因是板子还在默认的 auto 配置**：auto 和 screen 配置为了保留三个按键（K2 用的就是 GPIO10，舵机信号线的默认脚）从不初始化舵机 PWM，所以舵机永远收不到信号。只有 robot 配置重启之后，GPIO10 才交给舵机，并且舵机还要在这个应用的第 1 页长按之后才会通电。

在设备上打开“舵机校准”，第一页会告诉你现在是哪种情况：

| 第一页显示 | 意思 | 怎么办 |
| --- | --- | --- |
| 舵机未启用 / 长按 切到机器人配置 | 当前是 auto 或 screen 配置 | 长按 500 ms：保存 robot 配置并重启（舵机仍是断电的）；重启后如果还没存过校准会自动进入校准（存过的话从菜单打开），第 1 页再长按才通电。K2/K3 物理按键在 robot 配置里不再扫描，只剩 GPIO6 的 K1；想恢复，在设置的硬件配置页改回 auto，或 USB `python3 run.py hardware --set auto --reboot` |
| 舵机待重启 / 长按 重启生效 | 已保存了 robot 配置，还没重启 | 长按重启 |
| 舵机初始化失败 | robot 配置已生效但舵机 PWM 没起来 | 检查接线与 5V，板子日志里找 servo |
| 没有舵机 / 本固件不含舵机驱动 | 这是只含屏幕驱动的固件 | 换通用固件 |

接线：舵机信号线（黄/橙）接 GPIO10，红线接 5V（别接 3.3V，也别用 USB 口直接带大舵机，必要时单独供电并共地），棕/黑线接 GND。切换配置后再进校准：先不要装舵盘，第 1 页长按解锁并回中，舵机应该转到正中并停住；之后每页的短按都会让它立刻动。USB 里也能看：`robot status` 里 `armed=1` 表示已通电。

## 首次开机

没有保存过校准的机器人（NVS 里没有 `robot` 校准，用过 `robot save` 的不算）：开机顺序是 **屏幕设置 → 舵机校准 → 待机应用**。

- 在这里三连按是关掉的；第 1 页短按只是“先跳过”，**不保存**，下次开机还会问。
- 第 1 页 30 秒没有按键、后面几页 60 秒没有按键，都会直接进待机：舵机断电，校准恢复成进入时的样子，不保存，下次开机再问。
- 只有第 5 页长按才保存；保存后不再询问。想重新校准：菜单里的“舵机校准”；想让它重新当成没校准过：恢复出厂（会清掉校准）。

从菜单打开时行为一样，只是三连按可以退出（退出不保存，舵机恢复成进入时的校准），第 5 页长按保存后回到菜单。

## 实现

- 应用 `apps/servocal`，只用公共服务：`app_servo_cal_read/apply`（`esphook/app_services.h`）读写校准，`app_servo_request` 通电、转角和断电。`app_servo_cal_apply` 在舵机已通电时也可用（运动服务把舵机回到新的中位，方便观察），但不会让舵机通电，别的应用占着舵机时被拒绝。
- 运动服务队列里新增 `cal:<中位>,<摆幅>,<速度>,<反向>[,save]`（`robot_cal_parse/format`，纯函数，`./scripts/test-robot.sh` 覆盖），状态里的 `config_stored` 表示校准是不是存过的。`robot_start()` 在显示任务之前运行，所以应用管理器开机时已经知道舵机在不在、校准存没存。
- 开机提问用框架的 `first_run()` 回调：屏幕设置结束后按目录顺序继续问后面的应用（`screentest` 在 `servocal` 前面），都问完才进待机。

## 测试

- 主机：`./scripts/test-robot.sh`（校准行的解析/格式化）、`./scripts/test-app-games.sh`（`first_run` 的启动顺序与接力）、无屏 UI 测试（`./scripts/test-app-ui.sh`：五页文案与按键、舵机请求、保存、取消恢复、首次开机、超时、与屏幕设置的接力）。
- 实机：没有接舵机的板子只能验证“没有舵机”路径和开机流程；舵机真正转多少、方向是否朝你的左边，需要接上舵机在机器人上看。
