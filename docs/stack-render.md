# 切片堆叠渲染（`app_stack.h`）

把一个物体切成很多层很薄的 2D 像素片，竖直错开叠起来，再绕竖轴转一转：从斜上方看，一摞平片就成了**有厚度、能转、能倾倒的粗像素体**，不需要 3D 引擎，也不需要浮点。这是 2D 游戏做出立体感的常见办法（sprite stacking）。参考的网页小游戏（remix.ui8.ai 上的战斗机）的参数面板里就有“切片间距”“像素大小”“堆叠入场”：飞机、云都是一层层片堆出来的粗像素体，机身下有地面阴影，开场是切片一层层落下来拼成飞机。框架把这些能力做成了一个头文件，僵尸围城用它画僵尸、墓碑和手里的枪，极速赛车用它画车、树、路灯和龙门架，星际战机用它画小行星、敌机和你机翼上的炮。

`framework/include/esphook/app_stack.h`，纯 C、仅依赖 `app_gfx.h`/`app_math.h`（它们现在也不再依赖 LVGL，画布尺寸在 `app_canvas.h`），只在 UI 任务里画共享画布，不分配内存，栈上不到 600 字节。

## 模型：就是 ASCII 画

一层是一张俯视图，`d` 行、每行 `w` 个字符，`.` 是空，其它字符是调色板字母；`h` 层从下往上排。相邻字符串字面量会自动拼起来，所以每一层按行写，一眼能看懂：

```c
/* 一个 2 x 2 x 3 的块：每层 4 个字符，行 0 在最远处，最后一行是正面（yaw 为 0 时对着你） */
static const char *const BOX[] = {
    /* 0 */ "ss" "ss",
    /* 1 */ "ss" "ss",
    /* 2 */ "sk" "ks",
};
static const uint32_t PAL[] = {0x3060C0, 0xFFC040};
static const stack_model_t BOX_MODEL = {.layers = BOX, .keys = "sk", .colors = PAL, .w = 2, .d = 2, .h = 3};
```

| 字段 | 含义 |
| --- | --- |
| `layers` | `h` 个字符串，每个 `w*d` 字符，底层在前 |
| `keys` / `colors` | 调色板字母（最多 `STACK_MAX_KEYS` = 14 个）和对应的 `0xRRGGBB` |
| `alt` / `alt_n` | 可选：步态帧，`view.step` 为奇数时用这 `alt_n` 层替换最底下的几层（比如抬起一只脚） |
| `lit` | 可选：`keys` 里**最后** `lit` 个字母自发光，不受高度明暗、顶面光和描边影响（眼睛、灯） |

约定：体素在列 `u`、行 `r`、层 `l`；正 yaw 把正面转向观众的右边；`yaw` 是 0..255 对应一整圈；`scale` 等 `8.8` 的值是定点数（256 = 1.0）。`stack_model_valid()` 检查每层长度、字母是否在 `keys` 里和最底层非空，模型是常量数据，所以这个检查放在主机测试里，不进固件。

做模型时：

- **一个体素对应游戏世界的固定长度**（僵尸围城里 `ZM_VOXEL` = 5 个世界单位，行尸 20 层 = 100 单位），这样模型和碰撞/命中用同一套尺寸。
- **左右对称**：对称的模型可以用 `view.mirror` 左右翻转，僵尸就是用“抬脚帧 + 镜像”让两只脚轮流抬起。
- 只在需要的地方写细节（眼睛、血迹、瞄准具）：细节小于一个像素的距离上本来就看不清，近处才值得。

## 相机：两个入口

```c
stack_view_t v;
stack_view_init(&v);                    /* 先初始化，下面的辅助函数只改相机相关字段 */
v.x = 80; v.y = 50;                     /* 脚底中心落在画布的哪里 */
v.scale = 3 * 256;                      /* 每个体素边长 3 像素 */
v.yaw = now / 12;                       /* 转台 */
stack_view_pitch(&v, 20);               /* 固定仰角：0 平视 .. 64 正俯视（1/256 圈） */
```

- `stack_view_pitch(v, pitch)`：固定俯角的“追尾/俯视”相机（参考页面战斗机用的就是这种）。
- `stack_view_world(v, x, foot_y, z, voxel, eye, foc)`：第一人称相机看站在地面上的东西。`voxel` 是体素边长（世界单位），`eye` 是眼睛高出地面多少，`foc` 与平面精灵共用的焦距（`高度像素 = 高度 * foc / z`）。它还给出**层与层之间的透视**：低于眼睛的层露出顶面，高于眼睛的层露出底面；绘制顺序自动从离眼睛最远的那层开始，所以上下都不会穿帮。`eye` 取 0 时就等同于平面精灵的高度，取得比实际高一些（僵尸围城用 90，极速赛车的车用 2800 毫米）就像从肩后往下看，顶面更明显。

两者都是在设置 `ky0`（第 0 层每个体素深度对应屏幕多少行）、`ky_step`（每上一层变化多少）和 `squash`（层高系数，相当于仰角的余弦）。需要自定义相机时直接改这几个字段。

## 视图参数

| 字段 | 作用 |
| --- | --- |
| `x, y, scale` | 位置、每体素像素数（8.8） |
| `yaw` | 绕竖轴转，0..255 一整圈；转台、朝向、与屏幕位置相关的透视偏角都用它 |
| `ky0, ky_step, squash` | 相机，见上 |
| `build` | 0..256：堆叠入场进度。0 什么都没有，层从下往上一层层从高处落下拼好，256 是完整的（出场、复活、标题展示） |
| `lean` | 每层向一侧错开多少像素（8.8）：倾倒、前倾 |
| `squash` | 小于 256 就把模型压扁：倒下、被踩 |
| `tint, tint_amt` | 整体混入一种颜色：雾、受击闪白 |
| `dark` | 压向黑色：倒下后变暗、夜色 |
| `light, top_light` | 顶面接收的光色和程度（月光是偏蓝的顶面高光） |
| `shade` | 低层比高层暗多少（环境遮蔽，让体积更明显） |
| `edge` | 朝侧面敞开的体素压暗，勾出轮廓；0 关闭（也更快） |
| `palette` | 可选：替换整套颜色，每个个体一套（行尸的衬衫） |
| `step, mirror` | 步态帧和左右镜像 |

## 函数

| 函数 | 作用 |
| --- | --- |
| `stack_draw(px, model, view)` | 画模型，返回画了多少个体素（屏幕外或还没拼出来返回 0） |
| `stack_shadow(px, model, view, rgb, alpha)` | 地面软阴影，大小跟着脚印的朝向和相机走 |
| `stack_bounds(model, view, &x0,&y0,&x1,&y1)` | 画出来的像素一定在这个矩形里（未裁剪）：剔除、放特效、做点击范围 |
| `stack_project(model, view, col, row, layer, &x, &y)` | 某个体素中心在画布上的位置：枪口火光、火花、闪光、挂件 |
| `stack_yaw_seen(dx, foc_px)` | 固定摆在世界里的东西从你的眼睛看过去的朝向：在屏幕中线右边 `dx` 像素的东西露出它的左面，在左边的露出右面（`app_atan256`，整数反正切，256 = 一整圈）；加到它自己的朝向上 |
| `stack_model_valid(model)` | 模型格式检查（测试用） |

## 成本

每个**可见**体素约一两个小矩形填充（顶面、侧面）。`stack_draw` 返回的体素数就是这一帧的成本，一个场景可以自己设预算：

- 屏幕外的整个物体在包围盒这一步就被跳过；
- 远处（`scale` 小）自动**隔层只画**：每个体素 < 0.6 像素时每 2 层画 1 层，< 0.4 像素每 3 层画 1 层（画出来的层更厚），所以雾里的一排僵尸几乎不花钱；
- 近处被完全盖住的体素（上面有、四周都有）不画；
- `edge` 非 0 会多查四邻，只在近处开。

僵尸围城的真实对局：6 只僵尸 + 墓碑 + 枪约 1500 个体素；`tests/test_stack.c` 里有一个比任何真实对局都糟的合成场景（12 只僵尸全在眼前加全部 24 块墓碑全在屏上），平均 4800 个体素，上限断言 7000。UI 帧在 33ms 的预算里，LVGL 刷新和 SPI 才是大头。

## 僵尸围城里怎么用的

| 东西 | 怎么用 |
| --- | --- |
| 三种僵尸 | `zm_walker/runner/brute`（行尸 9×5×20，奔跑者 7×5×19，巨人 14×8×26）；`stack_view_world` 摆到和原来平面画法同样的位置和高度；每个行尸有自己的衬衫色（`palette`） |
| 朝向 | 转向横向摆动的方向（走左右“蛇形”时侧身）加缓慢蹒跚摇摆，所以随时能看见身体的侧面和厚度 |
| 步态 | 抬脚帧 `alt` 加每步左右镜像，两只脚轮流抬起；被击退/眩晕时站定 |
| 受击、倒下 | 受击闪白用 `tint`；倒下时 `lean` 向一侧倾、`squash` 压扁、`dark` 变暗，同时转一个角度 |
| 出场 | 远处走出来时 `build` 从 0 到 256，在雾里一层层拼出来 |
| 墓碑、十字架 | `zm_tomb/cross`，固定摆在世界里的朝向，随着视角转动（屏幕左右两侧的偏角），从另一面看到侧面和厚度 |
| 枪 | `zm_gun` 在 `stack_view_pitch` 相机下从身后上方看；转头时枪反向摆动，开火后坐、换弹下沉；枪口火光贴在 `stack_project` 算出的枪口上；每波开始枪一层层拼出来 |
| 标题 | 一对僵尸一层层拼出来，原地缓慢转动 |

## 极速赛车里怎么用的

路面仍是逐行算出来的伪 3D（那是地平线、路宽、弯道的真相），**路边和路上的东西**是体素模型，一个体素 `RM_VOXEL` = 285 毫米，所以车宽 3.1 米、长 4.6 米，和碰撞盒、路宽（6.96 米）是同一套尺寸。

| 东西 | 怎么用 |
| --- | --- |
| 三款车 | `rm_coupe/sedan/van`（跑车 11×16×6、轿车 11×17×7、厢式车 11×14×9）；每辆车按车道和颜色固定一款；车漆用 `palette` 替换车身两个字母（车身、车身阴影），尾灯是最后一个发光字母，刹车时变白；远处（体素小于 0.3 像素）退回一个色块加两点尾灯 |
| 朝向 | 车尾对着你，并随这一行路的方向转（弯道里车尾会朝弯的外侧偏），再加上 `stack_yaw_seen`：在你左边的车露出右侧面 |
| 相机 | `stack_view_world`，眼睛“作弊”抬到 2800 毫米（真实 1305），这样车顶和引擎盖看得见；`haze_amount` 给体素加一层和路面一样的远景雾（`tint`） |
| 树、路灯、龙门架 | 80 米内是 `rm_pine/round/post/gantry`；更远是原来的平面精灵，所以“弹出”发生在很远的地方；每棵树自己转一个角度；路灯的灯罩是发光字母 |
| 撞车 | 被撞飞的车转一整圈、闪白 |
| 成本 | 弯道里 3 辆车加十几棵树约 2000 个体素，撞车时约 1700；模型在生成时就去掉了所有看不见的体素（`hollow`），所以不依赖运行时剔除 |

## 星际战机里怎么用的

| 东西 | 怎么用 |
| --- | --- |
| 小行星 | `sm_rock_a/b/c`（9×9×9，种子选一款和一种色调；岩石明暗三色、陨坑、`g` 矿脉发光会脉动）；每颗体素大小随半径变（`半径×2÷9`），所以一颗石头不管多大都是 9 个体素宽；慢慢翻滚；被击中闪白；半宽小于 5 像素时仍是原来的平面圆 |
| 敌机 | `sm_fighter`（15×9×5，机头在最后一行朝向你）；`stack_yaw_seen` 的一半加一点左右摇摆，再加一个倾侧（`lean`）；充能时翼尖炮从红变琥珀色，眼睛红光脉动 |
| 你自己的炮 | `sm_cannon` 在 `stack_view_pitch` 相机下放在机翼两侧，朝准星内收；开火的火光贴在 `stack_project` 算出的炮口上 |
| 相机 | 一律是固定 28° 俯角（`stack_view_pitch`），不用 `stack_view_world`：东西漂在空中，没有地面可言；距离越远越被星空的深蓝雾吞掉（`tint`） |
| 仍是平面的 | 光弹、炮弹、爆炸、星空：它们是光，不是东西 |
| 成本 | 近景约 600 个体素 |
