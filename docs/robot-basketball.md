# GPIO6 投篮游戏

## 接线

新增一个常开按键：一端接 **GPIO6**，另一端接 **GND**。固件启用内部上拉，按下为低电平，无需额外上拉。GPIO6 专供该按键，不能再用于雷达或舵机；GPIO10 仍为舵机 PWM，GPIO20/21 仍为雷达串口。原 K2/K3 不接入机器人模式。

按键使用 GPIO 双边沿中断。ISR 只通知输入任务；任务在最后一次边沿通知后等待电平稳定 25ms，再产生按下/松手事件。空闲与长按期间任务阻塞，不做周期轮询；长按不连发。上电时若按键已按住，必须先松开再按，避免启动误触。

## 玩法

1. 待机短按打开启动器，选择“投篮”，按住 **500ms**（高亮条填满）进入。比赛中屏蔽了三击（连投不会退出），**按住按键 2 秒**随时回菜单，结算页任何短按直接回菜单；旧三击进投篮取消。进入时的松手不计出手。
2. 倒计时从 **02:00** 开始。篮筐从随机位置、随机方向出发，在屏幕内左右移动：撞到左右两端就**折返**，不会回到起点重来；中途每隔 **0.8–2.2 秒**随机换一个 **36–100 像素/秒**的速度，并有一半概率突然掉头。整条轨迹由每局的随机种子决定，是时间的函数，与刷新帧率无关。
3. 球从屏幕中央出手，约 **450ms** 后到达篮筐高度。**判定的是球到篮筐那一刻篮筐的位置**：篮筐中心进入屏幕中心 **±10 像素**范围即命中。墙上那条淡色竖带（和地板上的红色罚球区）就是这个窗口。篮筐在飞行时照常沿轨迹移动，所以要按“提前量”出手，而不是等篮筐走到正中再按；篮圈当前在窗口内会变绿，只表示此刻的位置。
4. 每次短按松手投一球，显示约 **650ms** 飞行/落球动画，期间额外短按忽略。球到篮筐时才显示结果：命中为绿色并加分，未进为红色，球飞行中提示“球飞行中”，命中的球穿过仍在移动的篮网，同时篮网鼓起、篮筐迸出火花、篮筐旁飘起“+2”；未进的球擦过篮筐，篮筐轻微抖动。
5. 篮筐不会因为出手而停下、重置或换速度；速度和方向只按上面的随机节奏变化。
6. 每投中一次得 **2 分**。时间到立即停止接收投篮，结算显示投中次数、得分、总出手数和整数命中率。

判定采用消抖后短按松手事件的时间戳加上 450ms，再取篮筐预定轨迹在该时刻的位置，独立于屏幕刷新次数；出手时即可算出结果，画面等球到篮筐才揭晓。650ms 动画也计入两分钟总时长；截止前已接收的投篮计入结果（即使球还没飞到），截止时及之后的投篮不计分。

游戏约 30 帧/秒刷新；按键事件和计时器仍由中断唤醒的输入任务及显示任务处理，雷达接收任务照常运行。

## 画面

场景用框架共享的 160×64 画布逐像素绘制（核心规则完全没变）：紫色渐变的竞技场墙面、观众剪影、广告牌、木地板（带向墙面收拢的木板缝和红色罚球区）；篮筐从天花板吊下，有玻璃篮板、红色目标框、前后篮圈和菱形篮网，篮网会随篮筐移动摆动，篮圈进入 ±10 像素窗口时变绿发光；球带阴影（越高越小越淡）、飞行拖尾，靠近篮筐时变小；命中时篮网鼓起、迸出一圈火花并飘起“+2”，未进时篮筐轻微抖动。顶部是随时间缩短的倒计时条（最后 30 秒变黄、10 秒变红并闪烁），时间/得分/进球数/提示是半透明小面板。结算页有渐变背景、随进球数增加的彩纸，以及按进球数 10 / 20 / 30 个点亮的三颗星。无屏测试里这个应用的 LVGL 64KB 堆占用约 12.5 KB。

## 结束与退出

结束后保留成绩页，短按返回菜单。任何时候 800ms 内三次有效按下回菜单，第三次松手被消费；前两次短按仍可能出手，以保留即时响应。重新从菜单确认进入即开始新局，清零数据并重新随机初始化篮筐轨迹。

游戏是临时覆盖层，不修改原表情/文字/雷达配置；回菜单后无操作 10s 恢复自动表情，其原有 TTL 仍按真实时间流逝。游戏期间通过显示协议仍可更新后台配置。详见 [全局启动器](robot-launcher.md)。

游戏不改变舵机的 arm/follow/校准状态，也不使用摄像头、麦克风或联网功能；只想安静玩屏幕游戏时，可先用现有 `robot disarm` 关闭 PWM。成绩保存在 RAM，不记录跨重启最高分。

## USB 调试命令

```text
robot game start
robot game status
robot game stop
```

- `start`：直接开始或重新开始一局，方便尚未接按键时调试。
- `status`：返回当前应用编号、菜单选择、剩余秒数、出手数、命中数和得分。
- `stop`：退出游戏并恢复自动表情，不影响舵机。`robot menu` 可直接开启动器。

命令和物理按键事件排入同一游戏队列，游戏状态与所有 LVGL 控件只由显示任务修改。

## 验证

```bash
./scripts/test-basketball.sh
```

纯 C 测试启用 AddressSanitizer/UBSan，覆盖按键抖动、中断合并后同电平仍重新消抖、开机按住、长按不连发、碰壁折返、随机轨迹（60 个种子：不跳变、不回绕、起点和方向各异、中途掉头、不同种子轨迹不同）、飞行中篮筐继续移动、按球到篮筐时刻判定的窗口边界、结果延迟揭晓、冷却时间、两分钟截止、成绩，以及完整对局模拟：完全预知的玩家全中，会读速度并提前量的玩家约 78%，盲投约 15%，旧习惯“篮筐在正中时按”只有约 5%。全局三击、入场不误计投篮、10s 超时和 PC 导航另由 `test-app-games.sh` 验证。原机器人/显示协议/主机测试与机器人和原 Hook 两种固件构建继续在 CI 运行。

尚未用新轨迹刷机验证；按键触感、屏幕动画和实际操作难度需要刷机确认。可调参数在 `apps/basketball/firmware/basketball_game.h`：`BASKETBALL_RIM_MS`（球到篮筐的时间，越小越好投）、速度范围、`BASKETBALL_LEG_MIN_MS/MAX_MS`（多久随机变一次）。
