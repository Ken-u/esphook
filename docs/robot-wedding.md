# 新婚快乐 / Happy Wedding（默认待机）

带彩带的祝福屏，也是**开机后的默认待机应用**：通电直接显示，菜单 10 秒无操作会回到这里，待机时收到 Hook 通知，仍按框架规则切到 Hook 应用（`APP_NOTIFICATIONS`）。

## 画面

- 中央横幅每 **4.6 秒**交替一次，切换时淡入淡出，四个字/各字母依次轻跳，一道高光从左到右扫过金色渐变字面：
  - 中文页：**“新婚快乐”**，下方金线夹着一颗跳动的红心，两侧各一颗星；
  - 英文页：两行 **“Happy / Wedding”**，左上角一对金戒指，四周飘着红心。
- **彩带**：顶部两侧垂下 8 条随风摆动的彩带；每次横幅切换，左右两个角**交替放一次礼花**（8 条拖尾彩带和 18 片彩纸），带阻尼先冲高、再卷曲垂落；全程还有 22 片彩纸缓缓飘落、星星闪烁。
- 底部 16 像素是**滚动祝福语**：百年好合 ★ 永结同心 ★ 幸福美满 ★ 白头偕老 ★ Wishing you a lifetime of love and happiness。

整个场景是 `app_gfx.h` 在共享 160×64 画布上按“进入后的时间”逐帧画出来的纯函数，没有逐对象状态，所以会话状态很小（编译期保证不超过 2048 字节会话区）；大字用 `apps/wedding/tools/gen_glyphs.py` 从思源黑体烘焙成 2 位灰度点阵（`wedding_glyphs.h`），因为设备字库只有 12/16 像素两档。

## 操作

- 短按：打开菜单（待机应用的统一行为）。其他操作交给框架（500ms 确认、全局三击）。
- 换成别的待机应用：设置应用的待机页，或 USB `standby` 操作（`link.request({"op": "standby", "app": "hook"})`）。设备上已保存过待机选择时，保存的选择优先于默认值，改回新婚快乐用同样的方法保存 `wedding`。
- **自定义祝福语**：PC 发应用消息，只改滚动那一行（最多 95 字节 UTF-8，空字符串恢复默认；字必须在设备 GB2312 字库里，否则显示为空白）：

```python
from esphook_sdk.link import AppLink
link = AppLink()
link.message("wedding", {"text": "祝小明和小红 百年好合 永结同心"})   # 消息 JSON 总长不超过 128 字节
```

## 默认待机怎么设的

应用描述符带 `APP_STANDBY | APP_DEFAULT_STANDBY`。开机时 NVS 里没有已保存的待机、或保存的应用已不存在/不能待机，就取带这个标志的应用（整个工程最多一个，`scripts/check-apps.py` 检查），没有则回退 `face`。用 `-DESPHOOK_APP_wedding=OFF` 去掉本应用后默认待机自动变回表情。

## USB 调试命令

```text
robot wedding status
```

返回 `active`（1 正在显示）、`page`（0 中文 / 1 英文横幅）、`frames`（已渲染帧数；两次读数除以时间即实机帧率）。

## 验证

`./scripts/test-app-ui.sh` 的无屏渲染会按时间采样两种横幅、礼花和淡入淡出，检查彩带在动、金色字存在、祝福语消息及字库覆盖；帧数、实际帧率和观感需要实机确认。
