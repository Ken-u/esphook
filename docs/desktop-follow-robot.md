# 桌面人体跟随转头机器人

状态：首版代码已实现雷达接收、位置关联、跟随状态机、PWM 输出、USB 校准与像素表情。构建和首次上机步骤见 [robot-bringup.md](robot-bringup.md)，硬件实测尚未完成。

## 分支与复用基础

- 开发分支：`feat/desktop-follow-robot`
- 起点：创建分支时的默认分支 `agent/install-agent-hooks`。
- 可复用：ESP-IDF 工程、ST7735 初始化与显示任务、USB Serial/JTAG CDC、配置存储、Wi-Fi、OTA。
- 此分支默认启用机器人模式；在 menuconfig 中关闭 `DESKTOP_FOLLOW_ROBOT` 可构建原 Hook 模式。
- 表情、投篮、雷达与跟随本地运行；USB 配网、HTTP OTA 和可选 device link 保留。Hook 可接主机 daemon，做 T 使用 PC 配套。

## 雷达协议依据

海凌科《LD2450 串口通信协议 V1.03》：

官方产品与资料入口：
https://www.hlktech.com/Goods-226.html

- 5 V 供电；文档要求电源供电能力大于 200 mA，此值不是整机电流预算。
- UART 为 3.3 V 电平，默认 256000 波特率、1 停止位、无校验。
- 输出最多三个目标的位置与速度。目标槽位不能直接视为可靠的人员身份。
- 实现时按协议样例核对有符号数编码，不能只根据产品页的 int16 描述直接转换。
- 实物固件版本、是否修改过串口波特率及工作模式仍需核对。

## 单 Type-C 供电设计边界

用户已确认 Type-C 接电脑，NHY009 使用 5V 供电。整机只取电脑的同一 USB/Type-C 输入，舵机与雷达从该输入的 5V 母线分支供电，所有模块共地；屏幕沿用 3V3 供电。舵机电流不经过主控的 3V3 稳压输出。最终接线需核对 SuperMini 的 VBUS/5V 引出和板上供电路径。

必须核对 SuperMini 实物的 VBUS/5V 引出、板上供电路径、USB 电源能力，以及 NHY009 启动/堵转峰值电流；仅凭 Type-C 接口形状不能证明整机电流足够。不预设需要额外电源。单路输入的去耦与布线随实物确认。

## 可先采用的行为草案（未由用户最终确认）

- 在前方区域内选择目标，锁定后优先保持，避免多人经过时频繁跳人。
- 雷达角度经滤波、死区和速度限制后生成头部目标角。
- 雷达数据过期与正常“无人”分开处理，超时后不继续使用旧坐标。
- 丢失目标短暂保持，再缓慢回正；超时时间、死区、速度和范围可调。
- 表情先做待机、发现、跟随、丢失四态，沿用现有显示任务统一刷新。
- 首次接舵机须使用实物参数做中位与小范围校准，完成限位确认后再自动跟随。
- 雷达通信故障时进入可见故障状态，不盲扫、不直接冲向极限角。

## 后续实现顺序

1. 确认硬件资料，落实 GPIO 和电源接线，区分已确认参数与配置默认值；机器人模式只启用 GPIO6 游戏按键并关闭旧 K2/K3 扫描，保留 USB CDC 配置入口。
2. 增加 LD2450 UART 接收和独立帧解析模块，覆盖分包、粘包、噪声重同步、正负坐标、空目标和过期数据测试。
3. 增加目标选择与跟随状态机；对目标跳变、丢失和转角限位做可复现测试。
4. 按已提供的 NHY009 脉宽规格实现 PWM 驱动与校准入口：1500 μs 中位，小范围初次校准，再开放 1000–2000 μs 跟随范围；重复频率和 3.3V 信号兼容性按剩余资料或实测核对。
5. 接入像素表情和现有配置/调试入口；本地跟随不等待网络连接。
6. 编译固件，实机检查转向、边界、静坐目标保持、多人切换、噪音、USB 供电下启动和转动稳定性。
