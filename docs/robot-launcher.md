# 单键启动器与全局输入

GPIO6 接常开按键，另一端接 GND，内部上拉。robot 配置仅使用此键；通用默认 auto 和 screen 保留 GPIO6/10/11 三个旧按键。USB 可模拟三键，参见 [发布指南](release-kit.md)。

## 交互

| 页面 / 动作 | 行为 |
| --- | --- |
| 正常待机（默认） | 新婚快乐彩带祝福屏（见 [robot-wedding.md](robot-wedding.md)）；可在设置里改成眼睛表情（眨眼、缓慢视线，人体跟随仍工作）、Hook 或雷达 |
| 待机短按 | 打开启动器一级菜单 |
| 启动器短按 | 蓝色高亮条在当前列表下移一行，到底回到第一个。一级列出游戏、日常和工具，二级列出对应应用 |
| 启动器按住 | 高亮条在 500ms 内自左向右匀速填满并在条下长出一条金线，预览板描边变金，填满后进入选中的分类或应用。提前松手按短按切换 |
| 双击（两次点击 ≤0.3s，之后 0.3s 内没有第三次） | 二级返回一级并恢复到对应分类。一级返回打开菜单时所在的应用。其他页面沿用应用历史 |
| 启动器无操作 10s | 运行设置中选择的待机应用（默认新婚快乐）；选表情时会清除临时显示覆盖 |
| 任何页面快速三次按下 | 800ms 内第三次有效按下直接回一级菜单，第三次松手被消费 |
| 投篮短按 | 松手即出手，无确认等待；长按不出手 |
| 做 T 按住 | 先暂停 K 线，500ms 确认买入后恢复回放，松手不卖出 |
| 雷达短按 | 回启动器 |

双击在第二次松手约 0.3 秒后执行，以便保留快速三击回一级菜单的手势。靠连按玩的游戏屏蔽三击时，同时关闭双击。详见 [应用框架](app-framework.md)。

靠连按玩的游戏可以屏蔽三击，改用长按 2 秒回菜单（小恐龙、投篮、水族箱、电子木鱼、星际战机、赛车、钓鱼；滑雪 3 秒），屏幕底部/面板会提示“按住2秒退出”，按住时有一条进度线，见 [应用框架](app-framework.md)。为了保留投篮和卖出的短按即时响应，**三击的前两次短按仍可能执行当前页面动作**；第三次抢占为菜单。进入程序的确认松手不会泄漏到新页面。长按确认不作为后续三击的第一次点击。

菜单是 iPod 风格的列表，图标由各应用的 `icon()` 画（篮球使用圆和线，股票使用蜡烛，雷达使用弧线；全部为 LVGL 图元，没有新增位图或整套图标字体）。

顶栏显示当前菜单和位置。左边一次显示四行，更多选项可滚动。右边预览当前分类或应用，并提示“长按进入”和“双击返回”。应用通过 descriptor 的 `menu_group` 加入分类，省略时进入“工具”。没有应用的分类自动隐藏。

## 代码复用

- `framework/core/app_input.c` 和公开头文件：GPIO 定义、25ms 消抖、三击、500ms 确认、进度和松手消费，与具体游戏无关。
- `input_task.c`：双边沿 GPIO 中断只唤醒任务；任务等待电平稳定后提交按下/松手。空闲或持续按住时不轮询 GPIO。
- `framework/core/app_manager.c` 与 ESP32 runtime 适配：全局导航与应用生命周期；输入任务只入队，显示任务处理状态和所有 LVGL 操作。
- `apps/launcher/firmware/app.c`：启动器的列表窗口、高亮条、滚动条、预览瓷砖和长按填充，图标由各应用的 `icon()` 绘制；后续应用可沿用同一套输入与导航。
- `app_manager.c` 的 `app_back()` 与双击手势（历史、起手屏、挂起窗口）：见 [应用框架](app-framework.md)。

USB 输入 `robot menu` 可直接打开菜单，`robot game start/stop/status` 保留给投篮调试。现有 `ui {...}` 和 HTTP 显示协议继续更新后台显示配置；启动器/游戏显示优先，菜单超时恢复自动表情。

## 验证

`./scripts/test-app-games.sh` 检查三击和双击的时间边界（快速三击仍是三击、慢三击读成双击、按住/取消/其他键都不算双击、屏蔽开关、起手屏、光标还原）、短按/长按互斥、确认只执行一次、松手消费、菜单超时、程序切换及 PC 前台状态；`./scripts/test-app-ui.sh` 渲染菜单的各个位置（顶部、滚动边缘、最后一页、滚动中途、按住一半）并断言每一步标题和 `n/N` 都在屏幕上；`./scripts/test-basketball.sh` 同时覆盖 IRQ 合并、抖动和开机按住。

设置、Hook、按键回传和示例也在启动器中；应用列表、生命周期及待机持久化见 [应用框架](app-framework.md)。
