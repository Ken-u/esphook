# 单键启动器与全局输入

GPIO6 接常开按键，另一端接 GND，内部上拉。robot 配置仅使用此键；通用默认 auto 和 screen 保留 GPIO6/10/11 三个旧按键。USB 可模拟三键，参见 [发布指南](release-kit.md)。

## 交互

| 页面 / 动作 | 行为 |
| --- | --- |
| 正常待机（默认） | 眼睛表情、眨眼和缓慢视线动画；人体跟随仍工作 |
| 待机短按 | 打开启动器 |
| 启动器短按 | 按注册表循环选择，每页三个图标 |
| 启动器按住 | 当前图标周围的圆在 500ms 内匀速填满，填满立即进入；提前松手取消确认并按短按切换 |
| 启动器无操作 10s | 运行设置中选择的待机应用；默认表情会清除临时显示覆盖 |
| 任何页面快速三次按下 | 800ms 内第三次有效按下立即回启动器，第三次松手被消费 |
| 投篮短按 | 松手即出手，无确认等待；长按不出手 |
| 做 T 按住 | 先暂停 K 线，500ms 确认买入后恢复回放，松手不卖出 |
| 雷达短按 | 回启动器 |

三击统一用于导航，旧的“三击进投篮”已取消。为了保留投篮和卖出的短按即时响应，**三击的前两次短按仍可能执行当前页面动作**；第三次抢占为菜单。进入程序的确认松手不会泄漏到新页面。长按确认不作为后续三击的第一次点击。

菜单按注册表分页，每页一行三个图标，图标上、标题下。篮球使用圆和线，股票使用蜡烛，雷达使用弧线；全部为 LVGL 图元，没有新增位图或整套图标字体。选框 160ms 平滑移动，菜单状态约每 16ms 更新，LVGL 由显示任务约每 5ms 调用；实际帧率需要实屏测量。

## 代码复用

- `framework/core/app_input.c` 和公开头文件：GPIO 定义、25ms 消抖、三击、500ms 确认、进度和松手消费，与具体游戏无关。
- `input_task.c`：双边沿 GPIO 中断只唤醒任务；任务等待电平稳定后提交按下/松手。空闲或持续按住时不轮询 GPIO。
- `framework/core/app_manager.c` 与 ESP32 runtime 适配：全局导航与应用生命周期；输入任务只入队，显示任务处理状态和所有 LVGL 操作。
- `apps/launcher/firmware/app.c`：启动器代码图标、选框动画和确认圆；后续应用可沿用同一套输入与导航。

USB 输入 `robot menu` 可直接打开菜单，`robot game start/stop/status` 保留给投篮调试。现有 `ui {...}` 和 HTTP 显示协议继续更新后台显示配置；启动器/游戏显示优先，菜单超时恢复自动表情。

## 验证

`./scripts/test-app-games.sh` 检查三击时间边界、短按/长按互斥、确认只执行一次、松手消费、菜单超时、程序切换及 PC 前台状态；`./scripts/test-basketball.sh` 同时覆盖 IRQ 合并、抖动和开机按住。

尚未接入实机；帧率、屏幕方向和按键触感需要刷机验证。

设置、Hook、按键回传和示例也在启动器中；应用列表、生命周期及待机持久化见 [应用框架](app-framework.md)。
