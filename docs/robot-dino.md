# 小恐龙（离线跳跃）

灵感来自 Chrome 断网页面的恐龙跑酷。单键游戏：恐龙固定在左侧自动奔跑，障碍物从右侧迎面而来，用同一个按键起跳。

## 玩法

1. 待机短按打开启动器，选择“小恐龙”，按住 **500ms**（高亮条填满）进入。进入时的松手不计输入。
2. 标题画面按一下键：开始奔跑并起跳。
3. **按下立即起跳**（不等松手）。**轻点就能越过所有地面障碍**，按住只是跳得更高、滞空更久：
   - 轻点：约 **27 像素**高、空中约 **0.64 秒**，能越过小/大/双仙人掌和低飞翼龙；
   - 一直按住：约 **38 像素**高、空中约 **0.78 秒**；
   - 空中再按无效，没有二段跳。
4. 障碍：小仙人掌、大仙人掌、双仙人掌；约 **150 分**后出现翼龙。**低飞翼龙要跳过去；高飞翼龙（悬在半空）站着从下面走过**就行——轻点正好跳进它的高度（会撞上）；用**按住的大跳**也能从它上面越过去。
5. 速度从 **80 像素/秒**起每秒增加 1.0，到 **170 像素/秒**封顶（90 秒）。得分 = 跑过距离 / 10，屏幕显示五位，每满 100 分分数闪烁，HUD 左边是最高分，最高分保存在设备上（`app_best`）：退出游戏、重启后仍在；只在一局结束时、且破纪录才写一次 flash。
6. 撞上障碍后恐龙变成“晕了”的样子，显示“游戏结束”，**500ms 内按键无效**（避免连点直接跳过结果），之后按键重新开始。超过先前最高分会显示“新纪录!”；首局不显示。

连点不会退出：小恐龙屏蔽了全局三击，**按住按键 2 秒**回菜单（开始和结束画面的提示会和“按住2秒退出”交替出现，按住时屏幕顶部有一条红色进度线）。

## 障碍保证可通过

障碍间隔按**时间**生成：相邻两个障碍到达恐龙的时间差随机落在 **1.15–2.3 秒**，按当前速度折算成距离，所以速度再快也留得出一次完整跳跃（0.78 秒）加落地余量。前 130 像素没有障碍；翼龙出现前不会遇到。

## 画面

用框架共享的 **160×64 画布**逐像素绘制：白天渐变天空、太阳、两层视差山丘、飘动的云；每 6000 像素白天和夜晚平滑交替（夜晚有星星、月亮、变暗的草地和泥土）；有草皮和泥土的地面、一路滑过的碎石和草丛；18×18 的恐龙（奔跑两帧、跳跃、晕倒），带阴影、起跳尘土、落地尘土和跑步时脚后的小尘；仙人掌、两帧拍翅的翼龙及其地面投影。上方是半透明 HUD，标题/结算是中央面板，操作提示在底部。点阵在 `dino_sprites.h`，字符键对应调色板，测试保证每行等宽、只使用约定的键。

## 实现

- `apps/dino/firmware/dino_game.{h,c}`：纯 C 规则，无 ESP/LVGL 依赖。**固定 1ms 步长**推进，结果只由随机种子和带时间戳的按键事件决定，与 tick/刷新频率无关；停顿超过 2 秒视为暂停而不是补算。游戏核心 136 字节，应用会话状态远小于 2048 字节会话区（编译期 `_Static_assert` 保证）。
- `apps/dino/firmware/dino_sprites.h`：恐龙（两帧奔跑、跳跃、晕倒）、两种仙人掌、翼龙（两帧）的点阵。
- `apps/dino/firmware/app.c`：共享画布绘制 + 少量 LVGL 小面板，绘图函数用 `framework/include/esphook/app_gfx.h`。退出时刷新共享画布，把它交给下一个应用。无屏测试里 LVGL 64KB 堆占用约 9 KB。

按键事件用 `DOWN` / `UP` / `CANCEL`：`DOWN` 起跳，`UP` 与 `CANCEL`（USB 按住租约失效）收跳。`SHORT` / `CONFIRM` 忽略，不再重复触发。

## USB 调试命令

```text
robot dino start
robot dino status
robot dino stop
```

- `start`：排队打开小恐龙；`stop`：回菜单；
- `status`：`phase`（0 待开始 / 1 奔跑 / 2 结束）、`score`、`best`、`speed`、当前屏幕障碍数。

## 验证

```bash
./scripts/test-dino.sh
```

纯 C 测试启用 AddressSanitizer/UBSan，覆盖：点阵每行等宽且只用约定字符、尺寸与物理一致；满按/点按/中途松手/越过顶点后松手的跳跃高度和滞空时间；无二段跳；落地/起跳时间戳；五种障碍的碰撞盒上下左右边界（刚好越过 / 刚好撞上）；不同 tick 节奏（5ms / 33ms / 一次性）逐字节相同的结果；十分钟级停顿；撞上后世界冻结、500ms 内不能重开、重开后最高分保留、新纪录判定；以及按键时间窗和机器人模拟：

- **按键时间窗**（对每种障碍在 80 / 125 / 170 像素/秒下逐 5ms 扫描）：**轻点**的合格窗口 205–425ms（最窄是慢速时的双仙人掌 205ms，即 ±100ms），按住 350–575ms；高飞翼龙上轻点会撞（撞击区间 665–805ms 的按键时刻），按住的大跳在其中仍有 105–245ms 能越过；
- 满按、把最高点对准障碍中心的“完美”玩家，12 个种子各跑 130 秒全部不死，速度达到 170 封顶，障碍间隔 1.15–2.30 秒，五种障碍都出现，150 分前没有翼龙；
- **只会轻点**的玩家（遇到高飞翼龙不跳）：12 个种子各 130 秒全部不死；
- 把按键时机统一提前或推迟 **±100ms**：轻点和按住两种玩法 12/12 种子都撑过 60 秒（按住在 ±140ms 仍全部通过；轻点 ±140ms 全部失败，仅打印）；
- 对高飞翼龙也轻点：12/12 死于高飞翼龙；对一切障碍都按住大跳：12/12 全部活过 60 秒。

真 LVGL 无屏渲染（`./scripts/test-app-ui.sh`）会开始游戏、起跳、落地、撞上并重新开始，并断言屏幕上的每个汉字都在固件字库里。

**尚未实机验证**：按键手感、30 帧/秒的实际流畅度（无屏测试不能证明 FPS）和肉眼难度需要刷机确认。可调参数在 `dino_game.h`：`DINO_JUMP_V` / `DINO_GRAVITY` / `DINO_MIN_HOP_Y` / `DINO_DROP_V`（轻点与满按的高度、滞空）、`DINO_SPEED_*`（速度曲线）、`DINO_GAP_MIN_S` / `DINO_GAP_MAX_S`（障碍间隔）。
